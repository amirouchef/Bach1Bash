Méthode de travail pour le projet

  1. Écris en français ce que fait ton outil, en 3 à 5 phrases, dans un fichier à part ou en commentaire. Ce sera la base de ton README.
  2. Liste les actions du menu (4 ou 5 maximum) et donne un numéro à chacune.
  3. Commence par le squelette ci-dessous : un menu qui revient, des actions vides qui affichent juste leur nom.
  4. Remplis les actions une par une. Après chacune : tu lances, tu testes avec un cas normal et un cas absurde, et seulement après tu passes à la suivante.
  5. Ajoute les protections : arguments manquants, fichier absent, saisie invalide, droits insuffisants.
  6. Relis : commentaires, indentation, noms de variables clairs.
Conseil : garde une copie de ta dernière version qui marche (cp projet.sh projet.sh.bak) avant chaque grosse modification.

Squelette de menu à adapter

#!/bin/bash
# projet.sh - Titre de ton projet
# Auteur(s) : ...

LOG="projet.log"

journal() {
    echo "$(date '+%F %T') - $1" >> "$LOG"
}

action_un() {
    echo "Action 1"
    journal "Action 1 lancee"
}

action_deux() {
    echo "Action 2"
    journal "Action 2 lancee"
}

afficher_menu() {
    echo "=== Mon projet ==="
    echo "1) Premiere action"
    echo "2) Deuxieme action"
    echo "0) Quitter"
}

while true; do
    afficher_menu
    read -p "Ton choix : " choix
    case "$choix" in
        1) action_un ;;
        2) action_deux ;;
        0) echo "Au revoir" ; break ;;
        *) echo "Choix invalide" ;;
    esac
done

Ce squelette contient déjà de quoi remplir une bonne partie du barème : une fonction, une boucle, une condition (case), un journal. À toi d’y ajouter des contrôles d’erreur et le vrai contenu.

Déboguer

bash -n projet.sh        # vérifie la syntaxe sans rien exécuter
bash -x projet.sh        # exécute en affichant chaque commande avec ses valeurs, précédée de +

Lis toujours le numéro de ligne dans le message d’erreur, mais regarde aussi quelques lignes avant : l’oubli d’un fi ou d’un done est signalé tout à la fin du script.
