Répéter sans se fatiguer

Système d’exploitation – Bachelor 1 – Séance 3 sur 4. Aujourd’hui, c’est le script qui travaille à ta place.

Lundi matin chez BashCorp : cinq nouveaux collègues arrivent. Il faut leur créer un compte, les mettre dans le bon groupe, et sauvegarder leurs dossiers chaque soir. À la main, c’est interminable.

Retour sur la séance 2

Ton devine.sh ne permet qu’un seul essai. Comment faire pour rejouer, sans copier-coller dix fois le même code ? Avec une boucle.

Les boucles

for : pour chaque élément d’une liste

for fruit in pomme poire kiwi; do
    echo "J’aime la $fruit"
done

for i in {1..5}; do echo "Tour $i"; done     # de 1 à 5
for f in *.sh; do echo "Script : $f"; done   # pour chaque fichier .sh du dossier

while : tant que la condition est vraie

compteur=1
while [ $compteur -le 5 ]; do
    echo "Tour $compteur"
    compteur=$(( compteur + 1 ))      # sans cette ligne, la boucle ne s’arrête jamais
done
Boucle infinie ? Si le script ne s’arrête plus, tape Ctrl+C dans le terminal.

Lire un fichier ligne par ligne

while read ligne; do
    echo "Ligne lue : $ligne"
done < liste.txt

Sortir de la boucle ou passer au tour suivant

MotEffet
breaksort de la boucle immédiatement
continuesaute le reste du tour et passe au suivant

Combiné avec case, ça donne le menu qui revient, que tu retrouveras dans le projet :

while true; do
    echo "1) Date   2) Quitter"
    read -p "Choix : " choix
    case "$choix" in
        1) date ;;
        2) echo "Au revoir" ; break ;;
        *) echo "Choix invalide" ;;
    esac
done

Les fonctions

Une fonction est un bout de script auquel on donne un nom, pour le réutiliser sans le recopier.

dire_bonjour() {
    echo "Bonjour $1 !"          # $1 = premier argument donné à la fonction
}

dire_bonjour Alice               # on l’appelle comme une commande
dire_bonjour Bob
  • Une fonction doit être définie avant d’être appelée, donc en haut du script.
  • Dans une fonction, $1, $2… sont les arguments de la fonction, pas ceux du script.
  • Une variable créée avec local x=5 n’existe que dans la fonction.

  • journal : ajoute à la fin du fichier journal.log une ligne du type 2026-11-04 14:32:10 - message.

Créer cinq utilisateurs d’un coup

Retour aux utilisateurs et aux groupes des premières séances, version automatique. Les commandes que tu connais déjà font le travail :

groupadd bashcorp                                   # crée le groupe
useradd -m -s /bin/bash -G bashcorp alice           # crée alice, avec son dossier perso, bash, dans le groupe
echo "alice:Changeme123" | chpasswd                 # fixe son mot de passe
getent group bashcorp                               # liste les membres du groupe

Ces commandes demandent d’être root. Ton script doit donc le vérifier (séance 2), puis lire la liste des noms dans un fichier.

Deux pièges : une ligne vide dans la liste ferait planter useradd (traite-la avec continue), et lancer deux fois le script ne doit pas créer deux fois les mêmes comptes (teste avec id). Le ! marche aussi devant une commande : if ! getent group bashcorp &>/dev/null; then.

Exercice 4 Le recrutement automatique

  1. Crée un fichier utilisateurs.txt avec 5 prénoms, un par ligne.
  2. Écris creer_users.sh, qui reçoit ce fichier en argument et :
    • vérifie qu’il est lancé en root, qu’un argument est donné et que le fichier existe ;
    • crée le groupe bashcorp s’il n’existe pas encore ;
    • pour chaque prénom : ignore la ligne si elle est vide, indique si le compte existe déjà, sinon le crée (avec son dossier, /bin/bash, le groupe, un mot de passe) ;
    • note chaque action avec ta fonction journal ;
    • affiche à la fin les membres du groupe.
  3. Lance-le avec sudo, puis une 2e fois : que se passe-t-il ? Vérifie avec id, ls /home et getent group bashcorp.

Bonus : force le changement de mot de passe à la première connexion (chage -d 0 nom) ; écris supprimer_users.sh qui supprime les comptes de la liste avec userdel -r, pour remettre la VM propre.

Un indice

Squelette : tests de départ, création du groupe, puis while read utilisateur; do ... done < "$1" avec un if id "$utilisateur" ... à l’intérieur. Si useradd est introuvable avec su seul, utilise su - ou sudo.

Le script de sauvegarde

tar permet de ranger un dossier dans une seule archive compressée :

tar -czf mon_archive.tar.gz mon_dossier      # c = créer, z = compresser, f = nom du fichier
tar -tzf mon_archive.tar.gz                  # t = lister le contenu (sans extraire)
tar -xzf mon_archive.tar.gz                  # x = extraire

Pour que chaque sauvegarde ait un nom unique, on y met la date et l’heure : date +%Y%m%d_%H%M%S donne par exemple 20261104_143210. Et basename extrait le dernier élément d’un chemin.

Défi Sauvegarde horodatée avec journal

Écris sauvegarde.sh qui reçoit un dossier en argument et :

  • vérifie qu’un argument est donné et que c’est bien un dossier ;
  • crée si besoin un dossier ~/sauvegardes ;
  • crée dedans une archive nommée sauvegarde_NOMDUDOSSIER_DATE_HEURE.tar.gz ;
  • teste si tar a réussi, affiche le résultat et l’écrit dans ~/sauvegardes/sauvegarde.log avec ta fonction journal.

Pour les plus rapides : note la taille de l’archive dans le journal (du -h) ; vérifie l’archive avec tar -tzf ; crée un script restaurer.sh qui extrait une archive donnée dans /tmp.

Un indice

if tar -czf "$DEST/$nom" "$1"; then ... else ... fi : le if teste directement la réussite de tar. Un message Removing leading / est normal, il ne signale pas une erreur.

Cron et projet

Démo : le script qui tourne tout seul

Pour finir, ton enseignant te montre comment lancer sauvegarde.sh automatiquement avec cron, le planificateur de tâches de Linux (à retenir, ce n’est pas obligatoire).

$ sudo apt install cron
$ crontab -e                       # ouvre ta liste de tâches planifiées
* * * * * /home/etudiant/scripts/sauvegarde.sh /home/etudiant/documents
Champminuteheurejour du moismoisjour de la semaine
Valeurs0-590-231-311-120-7 (lundi = 1)

Exemples : */5 * * * * toutes les 5 minutes ; 30 2 * * * chaque jour à 2h30 ; 0 8 * * 1-5 à 8h du lundi au vendredi. Utilise toujours des chemins complets dans le crontab, retire la ligne après le test (crontab -e ou crontab -r) et surveille avec tail -f ~/sauvegardes/sauvegarde.log.
